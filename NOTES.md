# NOTES — Parry Lab (тестовый полигон боёвки)

## Текущий этап
**M1 проверен.** Атака перенесена с ПКМ на E. Дальше — M2: атаки босса по данным + телеграфы.

Этапы: M0 скелет → M1 босс-мишень → M2 атаки босса по данным + телеграфы → M3 guard/парри/posture → M4 идеальный уклон, Focus, контратака, укол → M5 дошлифовка + README.

## Стек (закреплено)
phaser 3.90.0, vite 7.3.8, typescript 5.9.3. Node >= 20.19. Запуск: `npm install`, `npm run dev`. Проверка типов + сборка: `npm run build`.

## Принятые решения
- Логика в плоских мировых координатах; изометрия только в `src/world/iso.ts` (worldToScreen / screenToWorld / screenDirToWorld).
- Фиксированный шаг 60 Гц через аккумулятор в `scene.ts` (`update` → `tick`). Отрисовка интерполирует позицию между кадрами логики (prevX/prevY), чтобы на 144 Гц не было дёрганья. Debug-хитбоксы рисуются по реальной позиции логики.
- WASD — относительно ЭКРАНА (W = вверх по экрану), вектор переводится в мир. Скорость постоянна в мире, поэтому на экране бег по вертикали выглядит вдвое медленнее, чем по горизонтали (честная изометрия).
- Секторы прицела считаются в мире; сектор 0 центрирован на мировой оси +X. При N=4 границы секторов на экране — ровно вертикаль и горизонталь через игрока (сектор = экранная четверть: 0 низ-право, 1 низ-лево, 2 верх-лево, 3 верх-право).
- Автомат игрока: `state` + `stateFrame` в `player.ts`, переходы в `switch`. idle/move/attack; атака = startup→active→recovery (фазы считаются по `stateFrame`, 0 — кадр входа). Направление удара фиксируется в момент начала атаки.
- Буфер ввода (`ActionBuffer` в `input.ts`): события Phaser копятся между тиками, на тике переходят в буфер и живут `input.bufferFrames` кадров, пока автомат их не заберёт (`consume`). Несколько нажатий одного действия за тик = одно. Пока подключена только E (attack, без автоповтора при удержании); ЛКМ/пробел — в M3/M4.
- Хитстоп: тик логики идёт (slow-mo и F4 работают как обычно, по кадру хитстопа на шаг), но игрок, босс и буфер заморожены; нажатия во время хитстопа ждут и не стареют.
- Posture: удар игрока даёт `postureDamage`, регенерация через `postureRegenDelay` кадров без урона. Инвариант: спам ударов не заполняет шкалу — `checkPostureBalance()` пишет предупреждение в консоль, если config его нарушает. Полная шкала пока просто упирается в максимум (оглушение — M3).
- Коллизия тел: только в `combat.ts` (выталкивание игрока по линии центров). Попадание: сектор удара vs круг хёртбокса.
- Рестарт (R) — сброс состояния арены без перезапуска сцены (слушатели ввода не дублируются).
- Тела рисуются в порядке экранного Y.
- Вся отрисовка — один Graphics, перерисовывается каждый кадр; пол — отдельный статичный Graphics.
- Управление: WASD бег, E удар (направление — курсор), ЛКМ guard (M3), пробел dodge (M4). ПКМ свободна; контекстное меню браузера подавлено, иначе оно съедает keyup и WASD залипает.
- Debug-клавиши: F1 оверлей, F2 slow-mo, F3 пауза, F4 шаг кадра (на паузе).
- Цвета и размеры отрисовки тоже в config (`view`), отдельно от боевых чисел.

## Файлы
- `src/config.ts` — все числа
- `src/world/iso.ts` — проекция
- `src/input.ts` — снимок ввода на кадр логики (в мире)
- `src/player.ts` — автомат и движение игрока
- `src/boss.ts` — автомат босса (idle/hurt/dead), HP, posture
- `src/combat.ts` — коллизия тел, попадания
- `src/debug.ts` — оверлей, slow-mo, пауза/шаг
- `src/scene.ts` — цикл: фикс. шаг, хитстоп, камера, отрисовка, HUD, рестарт
- `src/main.ts` — запуск Phaser

## Известные проблемы
- (решено в M1) буферизация нажатий по кадрам логики.
- Нажатие, сделанное раньше чем за `bufferFrames` до конца удара, истекает (например, клик сразу после попадания). Так задумано, но если цепочка ударов ощущается «глухой», надо поднять `input.bufferFrames`.
