# Parry Lab — правила для агента

Тестовый полигон боёвки: одна изометрическая арена, один босс. Цель — довести до ощущения систему «читаю направление атаки → парирую → контратакую». Я не геймдевелопер: код пишешь ты, играю и даю обратную связь по ощущениям я.

## Стек (не менять)
TypeScript + Vite + Phaser 3, версии закреплены в package.json. Новые зависимости — только с моего согласия. Никаких внешних ассетов, всё фигурами.

## Архитектура
- Логика в плоских мировых координатах, изометрия только в src/world/iso.ts.
- Фиксированный шаг 60 Гц, тайминги в кадрах.
- Автоматы состояний игрока и босса, переходы явные.
- Все боевые числа только в src/config.ts, магических чисел в логике нет.
- Атаки босса — данные, а не код.
- Debug (F1, slow-mo, покадровый шаг) должен работать всегда.

## Процесс
- Работай этапами из NOTES.md. После этапа остановись и жди моего «дальше». Не делай ничего вне текущего этапа.
- Перед большими правками кратко опиши план и жди «ок».
- Правь только нужные файлы.
- Проверяй себя командой `npm run build` (типы + сборка). `npm run dev` НЕ запускай, я запускаю сам.
- Баг: сначала причина и логирование, потом правка. Две неудачные попытки подряд — остановись и опиши гипотезы.
- Если не уверен в API Phaser — смотри типы в node_modules, не выдумывай.
- В конце этапа: список изменённых файлов, что проверить руками, 3–5 параметров config для тюнинга, вопросы ко мне. Обнови NOTES.md.
- Отвечай кратко.
